# Matrix-v1 状态与最新口径

## 我们在测什么

DeepSeek V4.1 Flash 多供应商的速度/成本/稳定性/缓存行为，用于我们自己的选型，不是评测机构排名。

## 方法错误与修正

已发现并修正两处方法错误：

1. 旧批次把“UTF-8 字节数”当 token 规划输入，导致实际 prompt 只有目标 30-40%。
2. 旧批次把冷热请求同批并发发出，暖请求抢在冷请求完成前发送，产生“缓存 0 命中”的假象——这是调度错误，不是供应商问题。

## 现行口径

- 冷请求完成后再发暖请求（串行）。
- 输入按实测字节/token 组装并逐请求用真实 usage 回校。
- 输出预算≥512（64/256 时思维链常吃满预算导致看不到正文）。
- 费用一律标注为“按配置单价与上报 usage 的估算，非平台账单”。
